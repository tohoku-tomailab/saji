# 0001 基本構成

- 日付: 2026-09-23（HANDOFF.md の決定事項を記録したもの）

## 背景
研究室の実験データ処理を、(1) ターミナルに不慣れなメンバーがブラウザで、(2) AI エージェントが CLI で
使えるようにし、(3) 作成者の卒業後も保守できるようにしたい。

## 決定
- 実装は Python に統一し、処理ロジックは Python だけに置く。
- 共通のコアの上に CLI と Web を薄くかぶせる。
- Web は Pyodide（ブラウザ内 Python）を直接使う。サーバは持たず、静的ホスティング（GitHub Pages）で配る。
- Web の UI は素の HTML / CSS / JS。ビルドは Python のスクリプト1本（npm・バンドラなし）。
- ツール定義は Python の1か所に書き、CLI・Web のフォーム・ドキュメントをそこから作る。
- 実験データはリポジトリに入れず、Web でもブラウザの外に送らない。
- エージェント向けの説明は AGENTS.md に置き、CLAUDE.md は置かない（Claude Code 2.1.277 以降は
  CLAUDE.md がなければ AGENTS.md を読む）。
- 既存の kaiseki-tool は改修せず、saji を新しく作って移植する（人間の指示）。

## 却下した案
| 案 | 理由 |
|---|---|
| Streamlit / Gradio | デザインの柔軟性が低い。HTML/CSS は AI に書かせたほうが自由度が高い |
| サーバで動く Web（FastAPI など） | 卒業後に維持できない。未発表データをアップロードさせたくない |
| Web 用に処理を JS で再実装 | 二言語に分かれて片方だけ更新される。後任は JS を書けない |
| CLI だけを配布 | ターミナルに不慣れなメンバーが使えない |
| エージェント向け MCP サーバ | 今は不要。よい CLI で足りる。要るなら CLI の上に薄く足す |
| ツールごとの HTML ページ | JS の保守が増え、Python しか書けない後任が触れない |
| グラフの描画を手法ごとに JS で書く | 手法の知識が JS に散らばる |
| CLAUDE.md を置く | AGENTS.md が読まれなくなる |
