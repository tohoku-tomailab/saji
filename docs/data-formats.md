# 入力フォーマット辞書

装置やデータの種類ごとの入力形式・列名・単位・既知の癖。研究室固有の知識なので、
コードから読み取れることはすべてここに書く。分からない点は **要確認** と書いて人間に聞く。

## 共通

- 文字コードは自動判定（BOM → CP932 → UTF-8 → Latin-1 の順。`core/tableio.decode_text`）。
  装置の出力は CP932 が多い。BOM 付き UTF-8 は BOM を最優先で信じる（CP932 でも「読めてしまう」ため）。
- 表形式の入力は **列名で列を探す**（列順・列の有無・前置きの行に強い）。列名は全角/半角・大文字小文字・
  記号・空白を無視して照合する（`core/tableio.resolve_columns`）。

## Rigaku SmartLab .TXT（XRD）

- ツール: `xrd-process`
- CP932 のテキスト。先頭に測定条件のヘッダ（`Sample`, `Start`, `Stop`, `Step`, `X-Ray`,
  `ScanningMode`, `Goniometer`, `Attachment` などで始まる行）があり、そのあとに「2θ 強度」の2列が並ぶ。
- ヘッダの行数は一定でないので、**「数値2つだけの行」をデータ行とみなして**抜き出す。
- 2θ の単位は deg、強度は counts。
- 要確認: `*RAS_INT_START` などの区切り行の有無、ステップ・範囲の典型値、1ファイルの大きさ。

## ピーク表 JSON（XRD のピーク帰属）

- ツール: `xrd-process`（入力 `peaks`）
- `[[2θ, 物質名, マーカー, 色], ...]`。例 `[[43.30, "Cu(111)", "v", "tab:red"]]`。
- マーカーは matplotlib の記号（`v` `^` `o` `s` `D` `*` `x` `+`）、色は `tab:red` などの matplotlib の
  色名か `#rrggbb`。マーカーと色は省略可（既定 `v` / `tab:red`）。

## 処理済み XRD .xy

- `xrd-process` の出力。先頭に `# 2theta  intensity  | bg=... smooth=... norm=... bin=...` の
  コメント行、そのあと `%.6f` の2列（2θ、処理後の強度）。

## 2列 .xy（処理済み XRD パターンなど）

- ツール: `xrd-overlay`（入力 `xy`）。`xrd-process` が出す `<名前>_processed.xy` がこの形。他装置の2列テキストも可。
- 形式: 1行に「x y」の2数値（空白またはタブ区切り）。`#` 以降はコメント。3列以上ある行は先頭2列を使う。
- 列: 1列目 = 2θ（deg）、2列目 = 強度（counts か規格化値。単位は任意）。
- 読み込みは numpy.loadtxt 相当（`core.tableio.load_xy_text`）。**ヘッダ行が `#` で始まらないファイル
  （SmartLab の生 .TXT など）は読めない**（警告して飛ばす）。
- フォルダを渡したときは `.xy` だけを拾う（`.txt` / `.dat` はファイルを直接指定する。拡張子の警告は出るが読める）。
- 要確認: 研究室で使う他装置の2列出力（ヘッダの付き方・区切り・文字コード）。

## CO2RR 測定CSV（co2rr-plot）

1行 = 1測定（試料）。列は名前で解決する（列順自由・余分な列は読み捨て）。

| 論理名 | 別名（全半角・大小・空白と `_ - / \ ( ) .` を無視して照合） | 内容 |
|---|---|---|
| sample_id（`id_col`） | id, sampleid, sample, 試料id, サンプルid | 試料ID。`labels` 辞書のキー |
| sample_name（`name_col`） | name, samplename, 試料名, サンプル名 | 試料名 |
| group | グループ, 群 | 群化キー（最優先のラベル元） |
| label | ラベル | 行ごとのラベル |
| H2 / CO / CH4 / C2H4 / CH3COOH / 1-PrOH / EtOH / HCOOH | hydrogen, 水素 / carbonmonoxide, 一酸化炭素 / methane, メタン / ethylene, エチレン / aceticacid, acetic, 酢酸, aa / 1proh, npropanol, propanol, 1プロパノール, nproh / ethanol, エタノール / formicacid, formic, ギ酸, fa | ファラデー効率（%）。数値以外・空欄は NaN |
| potential（`potential_col`） | v, 電位, voltage, e, 過電圧, overpotential | 電位（V）。過電圧を入れてもよい（軸名は `potential_label` で変える） |

- ヘッダ行の探索: `products` の先頭2つの**論理名**（既定 H2, CO）を含む行をヘッダとみなし、その前の
  測定条件などを読み飛ばす。見つからなければ先頭行をヘッダとする。
  既知の癖: 前置きがあり、かつ H2 / CO の列名が別名（Hydrogen など）だと読めない。
- ラベル（群）の決め方: `labels`（{sample_id: ラベル}）> `label_pattern`（正規表現。グループがあれば1つ目、
  一致しなければ元の文字列）> ラベル元の列（`label_col` > group > label > sample_name > sample_id）。
  ラベル元が空欄の行は集計から外れる（警告）。
- 集計: 同じラベルの行を平均。生成物の空欄は無視し、全て空欄なら 0.0。電位が全て空欄なら NaN。
  誤差 std（ddof=1）/ sem（std/√n）/ none。値が1つ以下なら 0。
- 並び: `label_order`（無いものは無視・書かなかったラベルは外れる）、無ければ CSV に出てきた順。
- 集計CSV `<名前>_co2rr_summary.csv`（utf-8-sig）: label, n, <生成物>, <生成物>_err …, potential, potential_err。
- 要確認: 装置・解析ソフトから出る元の CSV の実際の形式（前置きの有無、列名）、FE の合計が100%を
  超えるときの扱い、電位の基準（vs RHE / vs Ag/AgCl）の書き方。

## ポテンショスタット CSV（北斗電工 HZ 系など、《...》区切り。echem-extract）

- 文字コードは CP932 が多い（自動判定）。改行は CRLF（要確認: 機種・設定による差）。
- `《セクション名》` の行でセクションが切り替わる。値の行は **B列から**（行頭が空セル）`,キー,値1,値2,…`。
- 数値の書式: `-7.658742e-003`（指数が3桁）。

| セクション | 中身 | 使い方 |
|---|---|---|
| 《ファイル情報》 | `,測定項目情報,<コード>,<名前>` など | コードから測定種を判定 |
| 《測定情報》 | `,面積,1.000000,cm2`、`,参照電極,Ag/AgCl` など | `area_cm2` / `reference_electrode` |
| 《測定条件》《PGS設定》 | 設定電流・時間・周波数など | 使わない |
| 《測定フェイズヘッダ》 | `,フェイズ情報,<コード>,<名前>`、`,サイクル番号,N`、`,測定点数,N` | 次の《測定データ》の属性 |
| 《サイクル情報》 | `,開始時間,…`、`,終了時間,…` | 無いフェイズもある |
| 《測定サンプリングヘッダ》《解析データヘッダ》 | データ数など | 使わない |
| 《測定データ》 | 先頭行が列名、その後が数値行 | フェイズの表 |

- フェイズは《測定フェイズヘッダ》…《測定データ》の組が順に並ぶ。同じコードが複数サイクル繰り返されることがある。
- 測定項目コード: `0x0506` = CP（クロノポテンショメトリ）、`0x051C` = IMP（交流インピーダンス）。
  それ以外は未登録（要確認）。未知のコードは列から推定する（Re Z と Im Z があれば IMP、電位E があれば CP）。
- フェイズコード: `0x0600` = 本測定、`0x0601` = 自然電位測定。名前に「本測定」を含むものも本測定。
  ほかのコードは要確認。
- 列名は `<項目番号> <名前>`。項目番号は機種・設定で変わるので落としてから照合する。

| 例 | 論理名 | 単位（推定・要確認） | rename 後 |
|---|---|---|---|
| `1 時間t` | time | s | time_s |
| `2 電位E` | potential | V | E_V |
| `3 電流I` | current | A | I_A |
| `4 WE/CE` | we_ce | V | WE_CE_V |
| `自然電位` | rest_potential | V | rest_E_V |
| `16 周波数　f`（全角空白入り） | freq | Hz | freq_Hz |
| `17 Re Z` / `18 Im Z` | re_z / im_z | Ω | ReZ_ohm / ImZ_ohm |
| `|Z|` / `位相Φ`（要確認） | abs_z / phase_angle | Ω / deg | absZ_ohm / phase_deg |
| `種別`（値は `第1電流` / `第2電流`） | kind | 文字列 | kind |

- 既知の癖:
  - 列名の行の末尾にだけ余分なカンマがある。データ行はヘッダより短いことがある（空文字で埋める）。
  - 表の開始列は「列名の行で最初の非空セル」から決める（B列と決め打ちしない）。
  - IMP は高周波→低周波の順。低周波側では Im Z の符号がノイズで何度も変わるので、溶液抵抗は既定で
    **最初（高周波側）の符号反転**の前後2点の Re Z の平均（`rs_method=interp` で Im Z=0 への内挿）。
  - CP は大きくドリフトする（実データで -6.6→-3.0 V）。定常部だけ平均するときは `avg_range`。
    設定電流が途中で変わる（`種別` 列）ので、種別ごとの平均も出す。
  - 本測定は複数サイクルになることがある（`<名前>_main_cycle1.csv` …）。

## EC-Lab ASCII .mpt（Bio-Logic。mpt-cycle）

- 1行目が `EC-Lab ASCII FILE`。先頭30行以内の `Nb header lines : N` の N 行目（1始まり）が列名の行。
  その前は測定条件（使わない）。バイナリの `.mpr` は対象外（EC-Lab で ASCII に書き出す）。
- タブ区切り。列名の行とデータの行の末尾に余分なタブが付く（空の列名は捨てる）。
- 数値の書式: `1.000000000000000E+000`（指数3桁）。言語設定によってはカンマ小数（`1,000000E+000`。最初の
  カンマだけ `.` にして読む）。
- 文字コード: UTF-8 として読めなければ Shift_JIS（CP932）で読む（移植元と同じ）。移植元で動作を確かめた
  方式なのでそのままにしている（decisions/0010）。CP1252 で書かれた `µ`・`°` は半角カナに化けうる
  （列名に `µ` があると `I/ｵA` のようになる）。
- 必須の列: `cycle number`（または `cycle`。大文字小文字と空白の数は無視）。RHE に換算するなら電位
  `Ewe/V` または `<Ewe>/V`。`<...>` は EC-Lab の平均値の印。
- 電流の列は測定法で名前が違う（CV は `<I>/mA`、ほかは `I/mA` など）。図の既定の列はファイルごとに
  x = `E_RHE/V` → `Ewe/V` → `<Ewe>/V`、y = `I/mA` → `<I>/mA` → `I/A` → `<I>/A` → `I/µA` … の順で探す。
- 出力 `<名前>_cycle<N>[_RHE].csv`（1.5 は `cycle1p5`）: UTF-8 BOM 付き・CRLF・全欄をダブルクォートで囲む。
  列と値は元の文字列のまま（カンマ小数もそのまま）。RHE なら末尾に `E_RHE/V`（有効10桁の一般形式）。
- RHE 換算: E_RHE = E_measured + E(ref vs SHE) + (RT ln10 / F) × pH（R = 8.31446261815324、F = 96485.33212、
  T = 温度 + 273.15）。プリセット（25 ℃付近）: Hg/HgO (1 M KOH) 0.105 / Ag/AgCl (sat. KCl) 0.197 /
  Ag/AgCl (3 M KCl) 0.210 / SCE 0.244 V。**内部液の濃度・温度に合う値かを必ず確かめる**（Hg/HgO は KOH 濃度で変わる）。

## PHI .spe（XPS、バイナリ。xps-extract）

- `EOFH` までが ASCII ヘッダ（CRLF）、そのあとがバイナリ部。
- 実測した領域は `SpectralRegDef: <番号> <?> <領域名> <原子番号> <点数> <ステップ> <開始BE> <終了BE> …` の行だけ。
  `SpectralRegDefFull:` は「定義しただけ」の領域なので使わない。
- バイナリ部（リトルエンディアン）: 全体ヘッダ int32×4、領域ごとのテーブル int32×24
  （5番目=点数、19番目=バイト長、20番目=バイナリ部の先頭からのオフセット）、そのあと float32 の強度。
- x は開始〜終了 BE を点数で等分（小数6桁に丸める）。ヘッダとテーブルが食い違ったら（点数、バイト長 = 点数×4、
  範囲）エラーにする。**軸は装置の生の値で、チャージ補正は入っていない。**
- 領域名はアンダースコア（`Cu_LMM`）。Multipak は空白（`Cu LMM`）なので、照合では空白と `_` を無視する。
- 実データで Multipak の書き出しCSVと強度が全点一致することを確認済み（kaiseki-tool 時代）。
- 要確認: テーブルの名前の無い欄の意味、ソフトの版によるテーブル構造の違い、サーベイの領域名が常に `Su1s` か。

## Multipak Exporter .txt / .csv（XPS。xps-extract）

- ブロック: ラベル行、+1 エリア番号、+2 XLabel、+3 YLabel、+4 点数、+5 からデータ（`x,y`）が空行まで。
  書き出し設定によってはメタ情報が1行だけ（`offset=2`）。
- ラベルは前後の空白を除いて完全一致で探す。既定のラベルは `Survey`。
- **書き出し時にチャージ補正で軸がずらされている**（試料ごとに1つの値が全領域に一律。実データで +1.0906 /
  +0.4838 eV、C1s が約 284.6 eV にそろう）。.spe 由来と重ねるときは、その差を `energy_shift` で足す（x だけ）。
- 要確認: 基準値（284.6 か 284.8 eV か）。

## XPS 抽出CSV（`<試料名>_<ラベル>.csv`。xps-extract の出力、xps-plot の入力）

- UTF-8、CRLF、ヘッダ `x,y`。x = 結合エネルギー（eV）、y = 強度（`normalize` なら領域ごとに 0–1）。
- 試料名はファイル名（拡張子なし）をドットで区切った最後の部分（`20260713_Name.108.sampleX` → `sampleX`）。
  ラベルは空白と `_` を除く。
- xps-plot は `x` / `y` 列があればそれを、無ければ先頭2列を使う。

## XPS フィット結果 CSV（1ファイル = 1スペクトル。xps-fit）

- 列は名前で解決する:
  - energy: Energy / B.E. / BE / Binding Energy / eV / x（必須）
  - spectrum: Spectrum / Raw / Raw data / Data / Intensity / CPS / y
  - composite: Composite spectrum / Composite / Envelope / Fit / Fitted / Sum / Total
  - background: Background / BG / Baseline
  - residual: Residual(s) / Difference / Diff（無ければ spectrum − composite）
- それ以外の数値列はすべて個別のピーク（`[1/1]`, `[2/1]`, …）。ピークの値はバックグラウンドを含む。
- ヘッダ行は自動で探す（前置きの行を読み飛ばす）。BOM 付き UTF-8（Excel 経由）は BOM を優先する。
- ピーク列はフィット範囲の外が空欄のことがある。
- 要確認: どのソフト（CasaXPS / Multipak）の出力か、正確な列名。
